# Onyx logo and icon asset checklist

This file is the source-of-truth checklist for replacing Onyx branding. Keep the master artwork simple, high contrast, and readable at very small sizes.

## Recommended master files

Create these first. The smaller platform assets should be generated from them rather than redrawn independently.

| Asset | Recommended size | Format | Shape / notes |
|---|---:|---|---|
| Primary Onyx app mark | 1024×1024 | PNG, transparent | Square master. Keep important detail away from the outer ~10% safe area. |
| Primary Onyx app mark, vector | scalable | SVG | Preferred editable source for future exports. |
| Onyx wordmark | at least 1600×400 | PNG, transparent + SVG | Horizontal logo for About/setup/branding screens. |
| Onyx landscape brand art | 1920×1080 | PNG or WebP | Optional splash/about/background use. Avoid essential text near edges. |

## Desktop / Tauri application icons

Tauri can generate platform-specific icon bundles from a good square source. The project should ultimately keep a complete icon set under `src-tauri/icons/`.

| Asset | Size | Format | Used for |
|---|---:|---|---|
| Windows application icon | multi-size: 16, 24, 32, 48, 64, 128, 256 | ICO | EXE, taskbar, shortcuts, Explorer |
| Windows Store / installer tiles | 30×30, 44×44, 71×71, 89×89, 107×107, 142×142, 150×150, 284×284, 310×310 | PNG | Windows bundle assets when generated by Tauri |
| macOS application icon | 1024×1024 source | ICNS | Dock, Finder, app bundle |
| Linux application icon | 32×32, 64×64, 128×128, 256×256, 512×512 | PNG | Desktop menus, launchers, task switcher |
| Tray icon, if Onyx gains one | 32×32 and 64×64 | PNG, transparent | System tray/menu bar; use a simplified monochrome-friendly mark |

## Web / browser client

| Asset | Size | Format | Used for |
|---|---:|---|---|
| Favicon | 32×32 | PNG or ICO | Browser tab |
| Favicon high resolution | 48×48 | PNG | Browser/platform fallback |
| Apple touch icon | 180×180 | PNG | iOS/iPadOS home-screen shortcut |
| PWA icon | 192×192 | PNG | Installable browser client |
| PWA icon large | 512×512 | PNG | Installable browser client / splash |
| PWA maskable icon | 512×512 | PNG | Android/PWA adaptive icon; leave a generous safe area |
| Social/share preview, optional | 1200×630 | PNG or JPG | Repository/site previews if Onyx gets a public site |

## In-app branding

These do not have to be different designs. In most cases they should be exports of the primary mark or wordmark.

| Asset | Recommended size | Format | Used for |
|---|---:|---|---|
| Sidebar/app mark | 128×128 | SVG preferred, PNG acceptable | Main Onyx navigation |
| Setup/welcome mark | 512×512 | SVG or PNG | First-run setup |
| About/Credits mark | 512×512 | SVG or PNG | Settings → About/Credits when added |
| Empty-state watermark, optional | 512×512 | SVG or transparent PNG | Empty libraries / subtle decorative use |

## iBroadcast developer-app icon

This is a provider requirement and should remain separate from the general Tauri icon set.

| Asset | Size | Format | Notes |
|---|---:|---|---|
| iBroadcast developer app | **128×128** | **PNG** | Square. Onyx currently generates this exact asset from inside the app. |

## Live TV channel artwork

Custom channel artwork is user content rather than application branding.

| Asset | Recommended size | Format | Notes |
|---|---:|---|---|
| Live TV channel artwork | **1280×720** minimum recommended; 1920×1080 ideal | PNG, JPG/JPEG, or WebP | **16:9 landscape.** Keep the channel logo/title near the center so it survives cropping. |

Onyx can fall back to show/backdrop artwork for show-based channels. Genre and playlist channels can use custom art when a stronger identity is wanted.

## Practical design advice

- Start with the 1024×1024 square master and SVG source.
- Test the mark at **16×16** before accepting it. Fine detail that looks beautiful at 1024px can turn into noise in the taskbar.
- Prefer transparency for application marks.
- Do not put small text inside the square app icon.
- Keep a simplified version of the mark available for favicon/tray use.
- Do not manually upscale small artwork to create the master assets.
- Keep source artwork in a dedicated branding folder once the final design is chosen; generated platform sizes should be treated as build assets.
